# Binning and MAGs

Contigs are grouped into bins (metagenome-assembled genomes, MAGs), refined, checked and annotated.

| Step | Default | Change with |
| :--- | :--- | :--- |
| Binning | MetaBAT2, MaxBin2, COMEBin, SemiBin2 | `--skip_<binner>`; CONCOCT and VAMB with `--skip_concoct false`, `--skip_vamb false` |
| Refinement | Binette | `--refine_tool dastool`, `--skip_binning_refinement` |
| Which bins go downstream | raw and refined | `--postbinning_input raw_bins_only\|refined_bins_only\|both` |
| Domain of each bin | off | `--bin_domain_classification` (Tiara) |
| Quality | CheckM2 | `--binqc_tool checkm2,checkm,busco`, `--run_gunc` |
| Annotation | Prokka | `--bin_annotation_tool bakta` |
| Taxonomy | sourmash | `--bin_classifier gtdbtk --gtdbtk_db <release226>` |

## Binning and binning refinement

### Contig sequencing depth

Sequencing depth per contig and sample is generated by MetaBAT2's `jgi_summarize_bam_contig_depths --outputDepth`. The values correspond to `(sum of exactly aligned bases) / ((contig length)-2*75)`. For example, for two reads aligned exactly with `10` and `9` bases on a 1000 bp long contig the depth is calculated by `(10+9)/(1000-2*75)` (1000bp length of contig minus 75bp from each end, which is excluded).

These depth files are used for downstream binning steps.

:::{dropdown} Output files
- `Binning/depths/contigs/`
  - `[assembler]-[sample_id]-depth.txt.gz`: Sequencing depth for each contig and sample or group, only for short reads.
:::

### MetaBAT2

[MetaBAT2](https://bitbucket.org/berkeleylab/metabat) recovers genome bins (that is, contigs/scaffolds that all belongs to a same organism) from metagenome assemblies.

:::{dropdown} Output files
- `Binning/MetaBAT2/`
  - `bins/[assembler]-[binner]-[sample_id].*.fa.gz`: Genome bins retrieved from input assembly
  - `unbinned/[assembler]-[binner]-[sample_id].unbinned.[1-9]*.fa.gz`: Contigs that were not binned with other contigs but considered interesting. By default, these are at least 1 Mbp (`--min_length_unbinned_contigs`) in length and at most the 100 longest contigs (`--max_unbinned_contigs`) are reported
:::

All the files and contigs in these folders will be assessed by QUAST and BUSCO.

All other files that were discarded by the tool, or from the low-quality unbinned contigs, can be found here.

:::{dropdown} Output files
- `Binning/MetaBAT2/discarded/`
  - `*.lowDepth.fa.gz`: Low depth contigs that are filtered by MetaBAT2
  - `*.tooShort.fa.gz`: Too short contigs that are filtered by MetaBAT2
- `Binning/MetaBAT2/unbinned/discarded/`
  - `*.unbinned.pooled.fa.gz`: Pooled unbinned contigs equal or above `--min_contig_size`, by default 1500 bp.
  - `*.unbinned.remaining.fa.gz`: Remaining unbinned contigs below `--min_contig_size`, by default 1500 bp, but not in any other file.
:::

All the files in this folder contain small and/or unbinned contigs that are not further processed.

Files in these two folders contain all contigs of an assembly.

### CONCOCT

[CONCOCT](https://github.com/BinPro/CONCOCT) performs unsupervised binning of metagenomic contigs by using nucleotide composition, coverage data in multiple samples and linkage data from paired end reads.

:::{dropdown} Output files
- `Binning/CONCOCT/`
  - `bins/[assembler]-[binner]-[sample_id].*.fa.gz`: Genome bins retrieved from input assembly
  - `stats/[assembler]-[binner]-[sample_id].csv`: Table indicating which contig goes with which cluster bin.
  - `stats/[assembler]-[binner]-[sample_id]*_gt1000.csv`: Various intermediate PCA statistics used for clustering.
  - `stats/[assembler]-[binner]-[sample_id]_*.tsv`: Coverage statistics of each sub-contig cut up by CONCOCT prior in an intermediate step prior to binning. Likely not useful in most cases.
  - `stats/[assembler]-[binner]-[sample_id].log.txt`: CONCOCT execution log file.
  - `stats/[assembler]-[binner]-[sample_id]_*.args`: List of arguments used in CONCOCT execution.
:::

All the files and contigs in these folders will be assessed by QUAST and BUSCO, if the parameter `--postbinning_input` is not set to `refined_bins_only`.

Note that CONCOCT does not output what it considers 'unbinned' contigs, therefore no 'discarded' contigs are produced here. You may still need to do your own manual curation of the resulting bins.

### VAMB

  - `stats/[assembler]-[binner]-[sample_id]-vae*_clusters_unsplit.tsv`: TSV defining the output bin clusters without binsplitting.
  - `stats/[assembler]-[binner]-[sample_id]-log.txt`: VAMB log file.
  - `trainedfiles/[assembler]-[binner]-[sample_id]-latent.npz`: Numpy array of the latent embedding of the contigs.
  - `trainedfiles/[assembler]-[binner]-[sample_id]-abundance.npz`: Numpy array of the abundance of the contigs.

:::

### DAS Tool

[DAS Tool](https://github.com/cmks/DAS_Tool) is an automated binning refinement method that integrates the results of a flexible number of binning algorithms to calculate an optimized, non-redundant set of bins from a single assembly. nf-core/mag uses this tool to attempt to further improve bins based on combining the MetaBAT2 and MaxBin2 binning output, assuming sufficient quality is met for those bins.

DAS Tool will remove contigs from bins that do not pass additional filtering criteria, and will discard redundant lower-quality output from binners that represent the same estimated 'organism', until the single highest quality bin is represented.

> ⚠️ If DAS Tool does not find any bins passing your selected threshold it will exit with an error. Therefore you will not find files in the `Binning/DASTool/` results directory for that particular sample.

:::{dropdown} Output files
- `Binning/DASTool/`
  - `[assembler]-[sample_id]_allBins.eval`: Tab-delimited description with quality and completeness metrics for the input bin sets. Quality and completeness are estimated by DAS TOOL using a scoring function based on the frequency of bacterial or archaeal reference single-copy genes (SCG). Please see note at the bottom of this section on file names.
  - `[assembler]-[sample_id]_DASTool_summary.tsv`: Tab-delimited description with quality and completeness metrics for the refined output bin sets.
  - `[assembler]-[sample_id]_DASTool_contig2bin.tsv`: File describing which contig is associated to which bin from the input binners.
  - `[assembler]-[sample_id]_DASTool.log`: Log file from the DAS Tool run describing the command executed and additional runtime information.
  - `[assembler]-[sample_id].seqlength`: Tab-delimited file describing the length of each contig.
  - `bins/[assembler]-[binner]Refined-[sample_id].*.fa`: Refined bins in fasta format.
  - `unbinned/[assembler]-DASToolUnbinned-[sample_id].*.fa`: Unbinned contigs from bin refinement in fasta format.
:::

By default, both the raw bins (and unbinned contigs) from the actual binning methods and the binning refinement with DAS Tool will be used for downstream bin quality control, annotation and taxonomic classification. The parameter `--postbinning_input` can be used to change this behaviour.

⚠️ Due to ability to perform downstream QC of both raw and refined bins in parallel (via `--postbinning_input)`, bin names in DAS Tools's `*_allBins.eval` file will include `Refined`. However for this particular file, they _actually_ refer to the 'raw' input bins. The pipeline renames the input files prior to running DASTool to ensure they can be disambiguated from the original bin files in the downstream QC steps.

### Binette

[Binette](https://github.com/genotoul-bioinfo/Binette) is a fast and accurate bioinformatics tool developed for binning refinement in metagenomics. It is designed to construct high-quality Metagenome-Assembled Genomes (MAGs) by combining and refining the outputs from multiple binning tools. By creating new "hybrid bins" through set operations—such as intersections, differences, and unions—and evaluating their quality using CheckM2, Binette ensures the selection of the most complete and least contaminated genomic bins. It offers significant improvements over existing solutions like metaWRAP by providing enhanced processing speed and supporting an unlimited number of input bin sets, making it a powerful choice for researchers working with complex microbial genomic data.

Binette will remove contigs from bins that do not pass additional filtering criteria, and will discard redundant lower-quality output from binners that represent the same estimated 'organism', until the single highest quality bin is represented.

> ⚠️ Binette requires CheckM2 database to proceed. Please provide the `--checkm2_db` parameter with the path to a pre-prepared CheckM2 database.

> ⚠️ If Binette does not find any bins passing your selected threshold it will exit with an error. Therefore you will not find files in the `Binning/Binette/` results directory for that particular sample.

:::{dropdown} Output files
- `Binning/Binette/`
  - `stats/[assembler]-Binette-[sample_id]_final_bins_quality_reports.tsv`: Tab-delimited description with quality and completeness metrics for the refined output bin sets.
  - `stats/[assembler]-Binette-[sample_id]_input_bins_quality_reports/input_bins_*.[assembler]-[binner]-[sample_id].tsv`: Quality reports for the input bin sets.
  - `logs/[assembler]-Binette-[sample_id].log`: Log file from Binette run describing the command executed and additional runtime information.
  - `bins/[assembler]-Binette-[sample_id]-Refined-bin_*.fa`: Refined bins in fasta format.
  - `unbinned/[assembler]-Binette-[sample_id]-Unbinned-bin_*.fa`: Unbinned contigs from bin refinement in fasta format.
:::

By default, both the raw bins (and unbinned contigs) from the actual binning methods and the binning refinement with Binette will be used for downstream bin quality control, annotation and taxonomic classification. The parameter `--postbinning_input` can be used to change this behaviour.

### BUSCO

[BUSCO](https://busco.ezlab.org/) is a tool used to assess the completeness of a genome assembly. It is run on all the genome bins and high quality contigs obtained by the applied binning and/or binning refinement methods (depending on the `--postbinning_input` parameter).
By default, BUSCO is run in automated lineage selection mode in which it first tries to select the domain and then a more specific lineage based on phylogenetic placement.
If available, result files for the selected lineage are placed in the output directory.
If a lineage dataset is specified already with `--busco_db`, only results for this specific lineage will be generated.

:::{dropdown} Output files
- `Binning/QC/BUSCO/[assembler]-[binner]-[sample_id]/`
  - `[sample_id]-[lineage]-busco.batch_summary.txt`: Summary table of the BUSCO results for the bins in the sample.
  - `short_summary.generic.[lineage].[assembler]-[bin].{txt,json}`: A detailed BUSCO summary for each bin, available in both plain text and JSON format.
  - `[sample_id]-[lineage]-busco.log`: Log file of the BUSCO run.
  - `[assembler]-[bin]/`
    - `prodigal_output/predicted_genes/predicted.{fna,faa}`: Predicted genes by Prodigal in FASTA format.
    - `logs/`: Logs for each of the tools used by BUSCO.
    - `run-[specific_lineage]:`
      - `full_table.tsv`: A detailed table indicating the complete BUSCO gene list for the lineage, detailing their presence in the assembly.
      - `missing_busco_list.tsv`: List of BUSCOs that were not found in the assembly.
      - `busco_sequences/*/*.{fna,faa}`: Nucleotide and aminoacid sequences of all identified BUSCOs (single copy, multi copy and fragmented).
:::

If the parameter `busco_clean` is set to `false`, the BUSCO directory will preserve additional files, including outputs from the tools BUSCO utilizes and the `auto_lineage/` directory. This directory contains results for each lineage tested during automated lineage selection.

If the parameter `--save_busco_db` is set, additionally the used BUSCO lineage datasets are stored in the output directory.

:::{dropdown} Output files
- `Databases/BUSCO/`
  - `busco_downloads/lineages/`: All files and lineage datasets downloaded by BUSCO when run in automated lineage selection mode. (Can currently not be used to reproduce analysis).
:::

:::{dropdown} Output files
- `Binning/QC/`

### GUNC

### Assembly statistics (`assembly_stats.py`)

The assembly statistics script computes per-assembly metrics used by the pipeline for QC and summary reporting. It is a small Python utility that parses one or more assembly FASTA files and calculates common assembly-level statistics such as contig counts, total assembly length, N50/L50, longest contig, GC content, and counts of contigs above configurable length thresholds. The script is intended to be invoked by Nextflow processes (e.g., `modules/local/finalize/assemblybased/assembly_stats.nf`) and the bin QC subworkflow (`subworkflows/local/bin_qc.nf`).

:::{dropdown} What it does
- Reads an assembly FASTA and computes per-assembly metrics:
  - number of contigs (optionally applying a minimum contig length filter)
  - total assembly length (sum of contig lengths)
  - N50 and L50
  - longest contig length
  - mean and median contig lengths
  - GC percentage (overall)
  - counts of contigs above common thresholds (e.g., >1 kb, >5 kb, >10 kb)
- Produces a per-assembly TSV (one row per input FASTA / sample) for programmatic consumption.
:::

:::{dropdown} Output files
- `Binning/QC/AssemblyStats/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id].assembly_stats.tsv`
:::

:::{dropdown} Columns explained
- sample_id: pipeline/sample identifier
- input_fasta: input FASTA filename
- assembler: assembler name or pipeline-provided tag (optional)
- n_contigs: number of contigs counted (respecting min_contig_length if set)
- total_length: sum of counted contig lengths (bp)
- n50: N50 length (bp)
- l50: L50 count (number of contigs reaching N50)
- longest_contig: length of the longest contig (bp)
- mean_contig_length: arithmetic mean of contig lengths (bp)
- median_contig_length: median contig length (bp)
- gc_percent: percentage of G or C bases across all counted contigs
- contigs_gt_1000bp / contigs_gt_5000bp / contigs_gt_10000bp: counts above thresholds (thresholds configurable)
- min_contig_length_used: minimum contig length used for counts (e.g., 0 or 1000)
- runtime_seconds: elapsed time for the script run
:::

Notes and recommendations
- By default the script can count all contigs (min contig length = 0). For comparability across datasets, consider setting a minimum contig length (e.g., 1000).
- N50/L50 are computed in the conventional manner: sort contigs by descending length, compute cumulative sum, find the length where cumulative sum >= 50% of the total; L50 is the number of contigs contributing to that cumulative sum.

## Taxonomic classification of binned genomes

### sourmash

[sourmash](https://sourmash.readthedocs.io/en/latest/) is a tool for computing and comparing MinHash sketches of DNA sequences. It is used in this pipeline for taxonomic classification of trimmed reads. This significantly expands the range of operations that can be done quickly and in low memory.

Currently, the pipeline does not automatically download the sourmash database. Users must obtain pre-built databases from [ctbrown’s farm](https://farm.cse.ucdavis.edu/~ctbrown/sourmash-db/) or build their own following the instructions [here](../getting-started/databases.md#sourmash), and provide the `--sourmash_database` and `--sourmash_ksize` parameters corresponding to the database path and its k-mer length.

:::{dropdown} Output files
- `Taxonomy/sourmash`
  - `bins_csv/sourmash_csv_collected_mag.csv`: Path to the bins of `[sample_id]`, located in the Nextflow `/work/` cache folder. The CSV header is `name,genome_filename,protein_filename`.
  - `sketches/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id].batch.manysketch.zip`: Result of running `sourmash scripts manysketch`.
  - `sketches/single_sketches/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]/manysketch_output/zip_files/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id]_[ksize].sig.zip`: Result for `[sample_id]` and `[ksize]` extracted from `*.batch.manysketch.zip`. This profile can be adjusted via the `--sourmash_profile` parameter.
  - `fastmultigather/fastmultigather/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id].batch.manysketch_sourmash_gather.csv`: Result of running `sourmash fastmultigather` on `batch.batch.manysketch.zip` with the database provided in `--sourmash_database`. This file contains all raw information returned by `sourmash fastmultigather` for all `[sample_id]`.
  - `taxannotate/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id].batch.manysketch_sourmash_gather.with-lineages.csv.gz`: Result of running `sourmash taxannotate` on `*.batch.manysketch_sourmash_gather.csv` with the database provided in `--sourmash_taxonomy_csv`.   - `taxgenome/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]-[sample_id].classifications.csv`: Result of running `sourmash taxgenome` on `*.batch.manysketch_sourmash_gather.with-lineages.csv.gz`. This file contains aggregated taxonomic abundance information for all `[sample_id]`.
  - `summary/[sample_id]_combined_{sourmash_gather,sourmash_gather.with-lineages,genome_classification}.csv`: Summary files for each step: `sourmash fastmultigather`, `sourmash taxannotate`, and `sourmash taxgenome` for each `[sample_id]`.
:::

### GTDB-Tk

With `--bin_classifier gtdbtk --gtdbtk_db <release226>`, bins (and `--genome_input` genomes without a lineage) are classified with [GTDB-Tk](https://github.com/Ecogenomics/GTDBTk) `classify_wf` instead of sourmash, one call per sample. The summaries are converted to the same table as sourmash, so the bacterial routing works the same way.

:::{dropdown} Output files
- `Taxonomy/GTDB-Tk/`
  - `[bin_set]/[bin_set].{bac120,ar53}.summary.tsv`: GTDB-Tk classification summaries (lineage, closest reference, ANI, `warnings`).
  - `[bin_set]/[bin_set].log`, `[bin_set].warnings.log`, `gtdbtk.json`, `classify/`: GTDB-Tk logs and intermediate files.
  - `summary/[bin_set].gtdbtk_classification.csv`, `summary/[sample_id]_combined_genome_classification.csv`: classifications in the sourmash `genome_classification` format, used for routing.
:::

## Genome annotation of binned genomes

### Prokka

Whole genome annotation is the process of identifying features of interest in a set of genomic DNA sequences, and labelling them with useful information. [Prokka](https://github.com/tseemann/prokka) is a software tool to annotate bacterial, archaeal and viral genomes quickly and produce standards-compliant output files.

:::{dropdown} Output files
- `Annotation/Prokka/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]/[bin_filename].prokka`
  - `<samplename>.gff`: annotation in GFF3 format, containing both sequences and annotations
  - `<samplename>.gbk`: annotation in GenBank format, containing both sequences and annotations
  - `<samplename>.fna`: nucleotide FASTA file of the input contig sequences
  - `<samplename>.faa`: protein FASTA file of the translated CDS sequences
  - `<samplename>.ffn`: nucleotide FASTA file of all the prediction transcripts (CDS, rRNA, tRNA, tmRNA, misc_RNA)
  - `<samplename>.sqn`: an ASN1 format "Sequin" file for submission to Genbank
  - `<samplename>.fsa`: nucleotide FASTA file of the input contig sequences, used by "tbl2asn" to create the .sqn file
  - `<samplename>.tbl`: feature Table file, used by "tbl2asn" to create the .sqn file
  - `<samplename>.err`: unacceptable annotations - the NCBI discrepancy report.
  - `<samplename>.log`: contains all the output that Prokka produced during its run
  - `<samplename>.txt`: statistics relating to the annotated features found
  - `<samplename>.tsv`: tab-separated file of all features (locus_tag, ftype, len_bp, gene, EC_number, COG, product)
:::

### Bakta

[Bakta](https://github.com/oschwengers/bakta) is a tool for the rapid & standardised annotation of bacterial genomes and plasmids from both isolates and MAGs. It provides dbxref-rich, sORF-including and taxon-independent annotations in machine-readable JSON & bioinformatics standard file formats for automated downstream analysis. The output is used by some of the functional screening tools.

:::{dropdown} Output files
- `Annotation/Prokka/[assembler]-[binner/binrefine]-[rawbins/Binette/DASTool]/[bin_filename].bakta/`
  - `<samplename>.gff3`: annotations & sequences in GFF3 format
  - `<samplename>.gbff`: annotations & sequences in (multi) GenBank format
  - `<samplename>.ffn`: feature nucleotide sequences as FASTA
  - `<samplename>.fna`: replicon/contig DNA sequences as FASTA
  - `<samplename>.embl`: annotations & sequences in (multi) EMBL format
  - `<samplename>.faa`: CDS/sORF amino acid sequences as FASTA
  - `<samplename>_hypothetical.faa`: further information on hypothetical protein CDS as simple human readble tab separated values
  - `<samplename>_hypothetical.tsv`: hypothetical protein CDS amino acid sequences as FASTA
  - `<samplename>.tsv`: annotations as simple human readble TSV
  - `<samplename>.txt`: summary in TXT format
:::

If `--save_bakta_db` is specified, the output directory will also contain the requested database.

:::{dropdown} Output files
- `Databases/Bakta/`
  - `bakta_database/`: Bakta database files used for annotation.
:::

## Bin refinement notes

### DASTool

DAS Tool may not always be able to refine bins due to insufficient recovery of enough single-copy genes. In these cases you will get a NOTE such as

```bash
[16/d330a6] NOTE: Process MICROCOSM:BINNING_REFINEMENT:DASTOOL_DASTOOL (test_minigut_sample2)
```

In this case, bin refinement has not necessarily failed but was unable to complete the refinement. You will therefore not expect to find any output files in the `Binning/DASTool/` results directory for that particular sample.

If you are regularly getting such errors, you can try reducing the `--refine_bins_dastool_threshold` value, which will modify the scoring threshold defined in the [DAS Tool publication](https://www.nature.com/articles/s41564-018-0171-1).

### Binette

Binette requires CheckM2 database to proceed. When using this tool, you need to provide the additional parameter `--checkm2_db`.

Binette may not always be able to refine bins due to insufficient recovery of enough single-copy genes. In these cases you will get a NOTE such as

```bash
[16/d330a6] NOTE: Process MICROCOSM:BINNING_REFINEMENT:BINETTE_BINETTE (test_minigut_sample2)
```

In this case, bin refinement has not necessarily failed but was unable to complete the refinement. You will therefore not expect to find any output files in the `Binning/Binette/` results directory for that particular sample.

If you are regularly getting such errors, you can try reducing the `--refine_bins_binette_min_completeness` or`--refine_bins_binette_contamination_weight`value.


The output folders are described in [Outputs](../reference/outputs.md).
